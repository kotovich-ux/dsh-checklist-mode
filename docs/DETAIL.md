# Режим «Чеклист»

Строгий режим выполнения задач: сначала план по пунктам, потом выполнение строго по нему.

## Как пользоваться

В composer'е наберите `/checklist` — команда появится в меню «+» (секция Commands).

| Ввод | Что произойдёт |
|---|---|
| `/checklist` | Включает режим. Дальше отправляйте задачу обычным сообщением. |
| `/checklist <задача>` | Включает режим и сразу отправляет задачу агенту. |
| `/checklist off` | Выключает режим. |

## Что меняется в поведении

Пока режим активен, в системный промпт агента добавляется секция `checklist:policy`:

1. первым действием — план из пронумерованных шагов с критерием готовности, записанный в `todo_write`;
2. шаги выполняются по одному, по порядку, с отметкой `completed`;
3. завершённые шаги не пересматриваются, работающее не переделывается;
4. при любом выборе — вопрос пользователю через `ask_user_question`, а не догадка;
5. никаких «попутных» улучшений сверх чек-листа;
6. короткие ответы, финал — отчёт «пункт → результат».

## Как это выглядит в меню

Строка `/checklist` в меню «Команды» оформлена как штатные команды: иконка
(лист с двумя строками — у первой чекбокс с галочкой, у второй пустой),
название на языке системы и английское имя команды.

Сделано клиентской половиной плагина — [`client.js`](../client.js):

- В DSH 2026-11 иконка и локализованное название есть только у встроенных
  команд — таблица `HOST_FACES` в
  `@deepseek-ai/dsh-client-ui-commands/src/client/presentation.ts`; дескриптор
  хостовой команды несёт только `name`/`description`/`input.hint`.
  Публичный `ctx.commandUi` умеет лишь полностью клиентские команды
  (contribution — имя не должно совпадать с хостовой) и decorations (поведение,
  без иконки).
- Поэтому `client.js` оборачивает `CommandUiRuntime.candidates` — единственное
  место, где собираются строки меню, — и дорисовывает нашей строке
  `label`/`description`/`icon`.
- Подмена мягкая: если в новой версии DSH метода не станет, в консоли будет
  предупреждение, строка останется без иконки, а команда продолжит работать.

## Ограничения

- Ограничение мягкое: это текст системного промпта, а не запрет инструментов. Модель может отклониться, но получит явную инструкцию этого не делать.
- Состояние режима хранится в памяти процесса: после перезапуска Harness режим выключен, его нужно включить заново.
- Команда регистрируется в секции Commands меню «+»: список секции Add (File, Goal, Plan, Feedback) зашит в клиент и сторонним плагинам недоступен.
